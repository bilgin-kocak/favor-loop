---

Favor Loop finds loops of 15-minute favors between Edge City India residents: A reviews C's code, C teaches B yoga, B takes A's portrait, when no two of them could swap directly. It also finds two-way swaps and gift chains started by someone who only wants to give. A loop starts only when every member says yes, a no is never shown to the others, and every favor is confirmed by the person who received it.

**This is a reviewed app.** `join`, `answer`, `confirm` and `leave` write per-resident state, so, like Kismet, it needs a bridge module, the app server's `subject` separation and `MINI_APP_FAVORLOOP_KEY` set by staff (I will send the key privately). **The three public reads (`how_it_works`, `menu`, `board`) need no token and no identity, so they could ship first as a read-only bundle if that is faster for the team.**

- Live endpoint: https://favorloop.fly.dev/mcp (MCP `2025-06-18`, stateless, JSON answers, 32 KB cap, no redirects)
- Demo video of an agent using it: to follow (I will add the link here)

### Privacy in one breath

Members are keyed by an HMAC of `X-Village-Subject`; the subject is never stored or logged. Arguments never carry identity (any `residentId`, `subject`, `userId`, `telegramId` or `username` key at any depth is `invalid_arguments`). A handle is shown only to the people a member gives to or receives from, only after everyone said yes. The board is anonymous. `leave` deletes at once; all data is deleted on 30 Nov 2026. No third party receives anything.
